It leverages a lock-free Dual SPSC (Single-Producer Single-Consumer) ring-buffer architecture to decouple the core matching thread from network and persistence overhead.\n\n## Architecture\n\n1. **Binary TCP Ingress**: High-frequency clients connect via non-blocking TCP (using Linux `epoll`) and send raw 30-byte `Order` structs, bypassing HTTP/JSON overhead.\n2. **Core Matching Engine**: Uses a highly optimized limit order book pinned to a dedicated CPU core, achieving sub-microsecond internal matching latencies.\n3. **Dual Ring Buffers**: Matches are pushed into two parallel lock-free SPSC queues:\n    - **Kafka Producer Queue**: A background C++ thread dequeues trades and streams them asynchronously via HTTP to an out-of-process Node.js Kafka-inspired broker (`minikafka`) for Write-Ahead Log (WAL) durability.\n    - **Gateway Queue**: An embedded Mongoose server consumes trades and broadcasts them to real-time WebSockets UI clients.\n\n## Performance Limits (Benchmarks)\nIn isolated CPU microbenchmarks on modern hardware, the pure matching logic executes at:\n- **Median (p50):** ~160 ns \n- **p99 Latency:** ~365 ns \n\nIn End-to-End ingestion benchmarks constrained on a 2-core cloud environment (where ingestion, matching, and Kafka persistence compete for CPU time), the pipeline comfortably achieves **140,000+ orders/sec** throughput.\n\n---\n\n## How to Build and Run\n\n### Prerequisites\n- GCC (with C++17 support)\n- Node.js (v18+)\n\n### 1.
